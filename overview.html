Конвейер обработки обращения (LangGraph StateGraph)
Deterministic & Agentic

Защита от сбоев: детерминированные триггеры и проверка уверенности модели. Если уверенность < 0.6 или сработал критический триггер — безопасная эскалация оператору. 

flowchart TD
    Start([Входящее обращение]) --> AuthCheck{Авторизован @misis.ru?}
    AuthCheck -- Нет --> Block[Требование входа / привязки]
    AuthCheck -- Да --> CleanText[Маскирование мата + определение языка]
    
    CleanText --> Splitter[Сплиттер составных вопросов]
    Splitter --> Classifier[LLM-классификатор + Triggers]
    
    Classifier --> ConfidenceCheck{Уверенность ≥ 0.6 и нет триггера?}
    ConfidenceCheck -- "Низкая уверенность / Триггер" --> Escalate[Безопасный маршрут: Эскалация оператору]
    
    ConfidenceCheck -- "Высокая уверенность" --> RouteBranch{Маршрут подзадачи}

    RouteBranch -- "auto_check" --> ExecDiag[Проверка misis.ru / LMS / Wi-Fi]
    RouteBranch -- "kb_rag" --> RAGSearch[Поиск в регламентах + Шаблоны]
    RouteBranch -- "cert_order" --> AutoOrder[Заказ справки с автопрофилем]
    RouteBranch -- "operator" --> Escalate

    ExecDiag --> DiagStatus{Сбой сервиса подтверждён?}
    DiagStatus -- "ДА" --> QuickNotice[Мгновенное извещение ≤ 2 сек без LLM]
    DiagStatus -- "НЕТ (сервис UP)" --> ClarifyQ[Шаблонный уточняющий вопрос ≤ 2 раунда]

    RAGSearch --> FoundCheck{Найден ответ в источниках?}
    FoundCheck -- "ДА" --> StrictAnswer[Ответ строго по регламенту с цитатой]
    FoundCheck -- "НЕТ" --> Escalate

    AutoOrder --> CertCreated[Статус: 'не обработана' → ЛК]

    QuickNotice --> IncidentCheck{ ≥ 3 жалобы за 15 мин?}
    IncidentCheck -- "ДА" --> MassIncident[Алерт дежурному + Баннер в админке]

    Escalate --> HumanDrawer[Карточка оператора: Саммари + Рекомендация]
    HumanDrawer --> CloseTicket[Решение оператора]
    CloseTicket --> AutoKB[Одной кнопкой: Черновик в Базу Знаний]

1
Клик-клик: Живая жалоба на Wi-Fi

Справка в военкомат или с места учёбы

Заказ через диалог с агентом → автоподстановка профиля → появление в ЛК со статусом 'не обработана'.

3

В админке жмём "Волна из 3 жалоб" → срабатывает детектор инцидента → пуш дежурному → массовый ответ.

5
Замыкание цикла: обучение базы знаний

Оператор закрывает заявку → кнопка "В базу знаний" → черновик статьи утверждён → бот уже отвечает по ней!

Мы создали ИИ-помощника технической поддержки НИТУ МИСИС — автономного агента на базе LangGraph и отечественной платформы Yandex AI Studio. Это не просто диалоговое окно, это полноценный цифровой инженер первой линии. [ДЕЙСТВИЕ: Показываем экран входа и форму подачи] Смотрите, как это работает. Студент входит под своей почтой МИСИС. Система сразу подтягивает его контекст — кто он, какая группа, какие обращения были ранее. Ключевая фишка номер один — умная диагностика и нулевые галлюцинации. Студент пишет: «Wi-Fi EDU не пашет». Агент не выдумывает совет. Он сам вызывает встроенный инструмент диагностики. Если сервис действительно лежит — студент за 2 секунды получает шаблонное подтверждение: «Сбой известен, инженеры уже чинят». Никаких лишних затрат токенов, мгновенный ответ! [ДЕЙСТВИЕ: Переключаемся в админку оператора → Тест-панель] Фишка номер два — детектор массовых инцидентов. LLM генерирует структурированный черновик, оператор жмёт «Утвердить» — и агент уже умеет отвечать на этот вопрос без человека!
